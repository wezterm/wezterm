# `format-toast-notification`

{{since('nightly')}}

The `format-toast-notification` event is emitted when a pane has requested a
toast notification using one of the escape sequences described in
[notification_handling](../config/notification_handling.md), and that option
has decided that the notification should be shown.

Its purpose is to allow you to decide how the notification looks, or to
prevent it from being shown, from your configuration file.

The event is not emitted for notifications that are generated by
[window:toast_notification](../window/toast_notification.md) or by wezterm
itself.

The parameters to the event are:

* `window` - the [Window](../window/index.md) that shows the pane, or `nil`
  if no window shows it; for example, when the pane belongs to a workspace
  that isn't the active one.
* `pane` - the [Pane](../pane/index.md) that requested the notification
* `notification` - a table with the fields:
    * `title` - the title that the pane asked for, or `nil` if it didn't
      specify one. `OSC 9` has no title.
    * `body` - the text of the notification

The return value of the event can be:

* nothing, or `nil` - the notification is shown with its default look: the
  title, or the body if there is no title, is shown as the heading, and the
  body is shown below it when there is a title.
* `false` - the notification is not shown
* a table that may have the following fields; the fields that are omitted
  keep their default values:
    * `title` - the heading of the notification
    * `message` - the text below the heading. Use an empty string to leave it
      out.
    * `attribution` - a less prominent line of text that is shown below the
      message. *Windows only.*
    * `silent` - if `true`, the system doesn't play its notification sound;
      overrides
      [toast_notification_silent](../config/toast_notification_silent.md)
      for this notification. *Windows only.*
    * `duration` - `"Short"` or `"Long"`: overrides
      [toast_notification_duration](../config/toast_notification_duration.md)
      for this notification. *Windows only.*

Only the first handler that was registered for the event is called. The
handler may call asynchronous functions. If it raises an error, or returns
something else than described above, the error is logged and the notification
is shown with its default look.

This example shows the title of the tab, or of the pane if the tab has no
title of its own, below the text of the notification, so that you can tell
where it came from:

```lua
local wezterm = require 'wezterm'

wezterm.on('format-toast-notification', function(window, pane, notification)
  local tab = pane:tab()
  local source = tab and tab:get_title() or ''
  if source == '' then
    source = pane:get_title()
  end
  return { attribution = source }
end)

return {}
```

This example uses the name of the foreground process as the heading, and
doesn't show notifications from panes that are running `make`:

```lua
local wezterm = require 'wezterm'

wezterm.on('format-toast-notification', function(window, pane, notification)
  local process = pane:get_foreground_process_name() or ''
  local name = process:match '([^/\\]+)$' or 'wezterm'
  if name == 'make' then
    return false
  end
  return {
    title = name,
    message = notification.title
      and (notification.title .. ': ' .. notification.body)
      or notification.body,
    silent = true,
  }
end)

return {}
```
