# `win32_focus_alt_key_workaround = "Always"`

{{since('nightly')}}

Windows only allows a process to bring one of its windows to the front in
certain situations; otherwise the taskbar button of the window flashes
instead. To get around that restriction, wezterm simulates a press and
release of the `ALT` key before it asks Windows to bring a window to the
front.

The simulated key press is seen by whichever window has the focus at that
moment, which can have visible effects, such as highlighting the menu bar of
that window.

This option controls that workaround. It applies whenever wezterm brings a
window to the front: [window:focus()](../window/focus.md),
[ActivateWindow](../keyassignment/ActivateWindow.md),
[ActivateWindowRelative](../keyassignment/ActivateWindowRelative.md), and a
click on a toast notification that was generated by a pane.

Possible values are:

 * `"Always"` - always simulate the key press first. This is the default,
   and is what earlier versions did.
 * `"WhenNeeded"` - ask Windows to bring the window to the front, and only
   simulate the key press and ask again if Windows reports that it refused.
 * `"Never"` - never simulate the key press. If Windows refuses, the taskbar
   button of the window flashes.

```lua
config.win32_focus_alt_key_workaround = 'WhenNeeded'
```

The option is read each time a window is brought to the front, so a change
takes effect when the configuration is reloaded.

This option has no effect on other systems.
