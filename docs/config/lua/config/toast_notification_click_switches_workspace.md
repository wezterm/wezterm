# `toast_notification_click_switches_workspace = false`

{{since('nightly')}}

Controls what happens when you click on a toast notification that was
generated by a pane that belongs to a
[workspace](../../../recipes/workspaces.md) other than the active one.

Clicking on such a notification always activates the pane and its tab within
their window. The windows of a workspace that isn't active aren't shown, so:

 * `false` - nothing else happens; you see the pane when you next switch to
   its workspace. This is the default.
 * `true` - wezterm also switches to the workspace of the pane, and brings
   the window that contains the pane to the front.

```lua
config.toast_notification_click_switches_workspace = true
```

Clicking on a notification is described in
[notification_handling](notification_handling.md); it is currently only
supported on Windows, so this option has no effect on other systems.
